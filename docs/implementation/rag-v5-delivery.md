# 本地知识库 v5：安装、使用与回退

本次功能在本机实施，未同步 GitHub。桌面应用仍叫 Shiping 1.0，管理网页显示“本地知识库”。原件与清洗结果、人工修订、SQLite、Chroma 分别承担原始归档、可追溯正文、事务记录和检索索引的职责。

## 使用

1. 手动启动本项目服务，浏览器打开 `http://127.0.0.1:18080/`。
2. 在“资料库”选知识库，上传文件。队列逐个发送文件，显示真实上传进度；一个失败不会阻止其他文件，可单独取消或重试。后台自动解析、清洗、转换 Markdown、增量更新索引；无需清洗按钮。
3. “任务与索引”显示后台阶段及页数。低置信度 OCR、复杂布局、密码等异常会进入需处理状态。打开详情对照原件修正 Markdown，明确排除无效页后继续；不能把“已接收文件”当成“内容已准确入库”。正常文件无需逐个审核。
4. 进入“知识库问答”。默认沿用已授权的桌面 DeepSeek 对话模型，首次需启动桌面并等待设置同步。保存成功后网页可独立问答，桌面可以关闭。也能在“设置与维护”填写网页独立模型，之后桌面不会覆盖该配置。
5. Enter 发送，Shift+Enter 换行；可新建/切换对话、停止回答、重新提问，展开参考资料查看本轮实际使用的片段、页码及版本。历史来源仅代表当时的证据，不保证仍是当前版本。只有成功完成的最近三轮用于追问，失败和中断的部分答案不作上下文。
6. “仅检索”不调用问答及改写模型。“按需整理问题”只在口语、长问题或指代问题时调用模型，原问题始终参与召回；改写超时、格式错误或改变原文标识时回退原问题。
7. 精排开关在“设置与维护”。开启后是向量40 + BM25关键词40 → RRF最多20 → 本机精排 → 去重/同章节邻片 → 最多8块、6000字符上下文。模型不可用会回退，诊断明确显示 disabled/applied/fallback。独立实体投票路线已移除。

## 模型、隐私与代理

OCR、解析、向量与精排均本地执行；真实问答将问题、最近必要对话及选中资料片段发送给用户配置的模型，问题改写也消耗额度。DeepSeek/网关模型需可用额度；不使用 Codex 自带 Key。阿里云仍负责桌面语音功能，与本机精排无关。

网页后台支持直连、HTTP(S) 代理和自定义请求头。桌面自动同步时解析系统代理，固定本次选择的首条路线；代理失败不会绕过到直连。系统端口变化后修改/重新应用桌面设置以重新同步。网页独立配置可填写代理地址，不支持账号密码代理及 SOCKS；这类路线会明确拒绝，不会改用本地 DNS 或直连。目标 HTTPS 保留证书校验；不跟随模型接口重定向。外部 API 地址必须 HTTPS，本机测试地址可 HTTP。密钥保存于 `local-rag/data/library/ai.json`（权限600），不回显、不写日志、不提交 Git；网页独立配置优先。

## 可复用精排服务

- 模型：`BAAI/bge-reranker-v2-m3`，固定版本 `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`。
- 独立环境：`local-rag/runtime/reranker-env/`；模型：`local-rag/models/reranker/bge-reranker-v2-m3/`。
- 模型与依赖不进入源码；`reranker/requirements.lock`、安装脚本及 SHA256 清单可重建环境。
- 在仓库根目录使用 Python3.12 运行 `python3.12 local-rag/scripts/setup-reranker.py`，安装约2.3GB权重及独立依赖；`--verify-only` 只校验。来源为官方 PyPI 与 Hugging Face 固定提交。MPS 可用时用 Apple GPU，失败明确回退 CPU。不开机自启。
- 启停：`python3 local-rag/scripts/manage.py start-reranker` / `stop-reranker`；常规 `start`/`stop` 在已安装时包含它。只启动核心向量服务仍用 `start-core`。
- 健康：`GET http://127.0.0.1:18200/health`。
- 其他本机项目可调用 `POST /rerank`，JSON `{ "query":"问题", "documents":["候选一","候选二"] }`。结果每项带输入 index 与 relevance_score；按分数从大到小排列即可。分数不是正确率。最多20条、问题3000字符、每片8000字符，实际配对不超过8192 tokens，不静默截断；繁忙返回429。服务仅供本机后台调用，带 Origin 的浏览器请求会被拒绝。
- 多项目复用需在 manifest.json 登记消费者，停止共享服务前检查其他项目。

## 测试结果及边界

固定七份资料的20题是检索回归集，并非独立的大样本准确率评估。稳定双路排序的首片关键词覆盖17/20；开启BGE精排后16/20，最终上下文所需概念覆盖两者均20/20。部分问题更好，部分问题首片变差，不能宣称精排必然提高准确率。该集未调用云端生成，不能称“回答准确率100%”。精排作为可切换功能供真实问题进一步验证。

M5、16GB 实测20个短候选热精排中位约0.15秒，固定资料题整次检索精排中位约1.11秒、P95约1.42秒（20题样本）。长片段及并行OCR会更慢；Python RSS 不包括全部GPU统一内存，不将其当成总占用。原先报错的5.5MB/79页PDF已完整解析79/79，发现的低质量文字仍需复核。

## 数据、备份与回退

SQLite 由5加法迁移到6，增加对话与消息，不重置资料、原件、人工版本或索引。旧程序不支持schema6，应停止服务并恢复完整v5切换前备份后再启动旧程序，不可只替换旧代码硬开新库。备份目录和应用副本见本机操作台账。

网页 JSON 资料备份及 Markdown 导出不包含聊天历史；完整系统备份包含 SQLite 对话、私有配置、原件及 Chroma。先退出桌面，停止本项目拥有的全部服务，再运行 `python3 local-rag/scripts/manage.py backup`。不要恢复运行中的数据库，也不要丢弃切换后的新资料。

## 关闭或移除精排

只想恢复原排序：在网页关闭精排开关，不用重建索引，向量库继续可用。释放运行内存：关闭开关后 `stop-reranker`。不再需要模型：先检查其他消费者并备份安装清单，再仅移除 `runtime/reranker-env/` 和 `models/reranker/`；这不删除SQLite、原件、Chroma、BGE-M3向量模型或OCR资源。`manage.py uninstall-plan` 是只读预览，不自动删除。完整卸载共享向量库应先备份资料并确认所有消费者都不用。
