# 上传反馈实现计划

目标：按用户已给出的要求，检查后直接修复 Shiping 和 Web 上传体验。

设计：原生界面在默认资料库列表顶部导入，流式发送原始字节到既有 HTTP 上传 API。主进程保管连接信息，向界面报告真实写入进度；服务端接收回执后才标记传输完成。解析任务与项目索引状态分别查询，不伪造处理百分比。Web 使用既有 XHR 队列补充处理状态。

约束：单文件 0–30MiB（不含零）、11 种已有扩展名、每批最多50个、保留未提交改动、不自动提交/发布。

- [ ] 传输：先测试流式字节、非法文件、取消、回执核对，再实现 desktop-upload 与 DesktopLibrary 接线。
- [ ] 原生反馈：IPC 事件报告每文件传输，轮询解析/索引，失败可重试；明确默认库和入口。
- [ ] Web反馈：先测试解析/索引状态，再补充队列轮询，接收与处理失败分开。
- [ ] 验证：相关回归、完整 Shiping 和 Web 测试、类型检查、构建；记录差异与限制。
