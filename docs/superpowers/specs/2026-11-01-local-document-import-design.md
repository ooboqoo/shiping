# 本地 OCR 与 Office 文档导入方案

用户已选择全部本地处理。目标是桌面与网页共享解析流程，提取结果进入现有清洗、结构化分片和索引；不使用云端 OCR，不改变现有资料与集合。

## 方案与取舍

建议采用跨平台本地 OCR 引擎及中英文识别资源，按需加载并缓存到项目管理的位置。相比 macOS 系统 Vision，此路线新增依赖和首次资源下载，但避免功能绑定 macOS，便于其他电脑安装；相比云端 OCR，识别不产生调用费、文件不发送到识别服务，但复杂版式识别效果和速度需实测。具体引擎与依赖版本在核对官方资料后锁定。

## 支持范围

- PNG、JPEG、WebP 图片：中英文 OCR。
- PDF：逐页检查可提取文字；无有效文字的页面本地渲染后 OCR，保留页码与原顺序。混合 PDF 不重复整页识别已存在的文字。含少量文字又有大幅图片的页面不保证图片文字全量识别，须明确说明。
- XLSX：按工作表、行顺序保留表头及单元格关系；读取保存的值，不执行宏，不自行计算公式。旧 XLS 先转换。
- PPTX：按页提取文字及备注，识别页中支持的位图文字；保留页码，区分文本与图片识别结果，不承诺完整视觉布局或阅读顺序。旧 PPT 先转换。

## 实现边界与错误处理

扩展共享解析入口和格式常量，同步桌面选择器、网页文件校验与上传提示。OCR 放在后台任务执行，避免阻塞界面；提供解析阶段提示与可读错误，设置超时、页数、像素和压缩解包上限，并在结束或失败时清理临时文件。文件仍限制 30 MB，解析后的正文沿用各入口现有限制并明确提示，不静默截断。

默认本地解析，不执行文档中的宏或脚本，不将文档中的指令当成系统命令。识别资源首次下载来源、大小、存储位置和移除方式记录于 README 与操作台账。

## 验收

使用合成中英文图片、扫描与混合 PDF、带空行及公式缓存值的 XLSX、含文字和图片的 PPTX 验证实际提取；测试损坏文件、资源缺失、超限、超时及临时清理。桌面与网页都能导入并检索样例中的独有事实，原有解析和测试不回退。同步 README、发布副本及 pcworkspace 副本；先确认各副本无用户新改动，禁止覆盖。
