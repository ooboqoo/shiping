# 本地知识库 v5：问题清单优化设计

状态：已完成设计检查；用户于2026-11-02批准实施，并明确安装本地reranker。来源：用户指定的《我发现几个问题.pages》七项问题，以及用户已确认“沿用已配置的DeepSeek，支持真实问答与按需改写”。本轮暂不上传GitHub。

## 目标与选择

让本地知识库上传稳定、清洗结果可用、操作一致，并提供基于证据的连续问答。沿用现有Node/SQLite/Chroma/Ollama，本机解析/OCR；DeepSeek仅处理用户问题、必要历史和选中片段，不接收整份原件。

比较方案：A只修上传、样式，保留纯检索与规则改写，成本低但无法满足真实聊天；B在修复基础上接入现有DeepSeek，支持聊天和按需改写，增加推理成本及模型连接配置。用户已选择B。开发者裁定：保留单一后台、保守数据清洗与可回退修订，不新增前端框架；本轮安装一款经用户确认的本地BGE-reranker-v2-m3模型。

## 1. 上传与恢复稳定性（最高优先级）

已复现：用户的《第3章 软件工程.pdf》5756834字节、79页，web/store.decodeBase64与library-v4/inputs.decode均在重复分组正则上RangeError: Maximum call stack size exceeded；发生在PDF解析之前，不是文件超限。

- 统一有界、线性Base64校验：长度、字符集、填充位置、解码字节数；不对数MB输入使用递归/回溯式分组正则，不取消内容和大小校验。覆盖上传、桌面RPC、备份恢复。
- 浏览器优先二进制上传，避免DataURL/base64整份膨胀；保留旧JSON接口兼容。仅一次性接收完整且通过限额校验的文件后才创建不可变原件和持久任务。中断/取消不制造空记录。
- 每个文件独立显示上传进度、后台处理阶段、成功/失败及重试；一个失败不阻断同批后续文件。取消、网络中断、重复提交、服务重启都有明确状态。
- 重复原件在上传结果中明确“复用”，不重复OCR/向量化。超过30MB、150页、正文上限等用中文解释，不能把规则拒绝伪装程序崩溃。
- 为长扫描PDF提供页级进度和可解释的超时：持续有进展时允许完成，在无进展和总时长上设置有界保护。仍为单重任务队列，支持取消，内存有界。

## 2. 清洗与OCR质量

目标是保留可靠内容、去掉有依据的噪声；不能通过删除不认识的内容来伪造识别正确。

- 文本级清理：BOM/换行/无意义控制字符、明确不可见噪声、孤立装饰/列表残片及有位置证据的重复页眉页脚、页码；保留真实标点，不盲删句号或全角符号。
- 结构保护：围栏代码、URL、公式、数字、表格、标题与有效列表不套用普通段落的标点删除和续行合并规则。
- OCR保留实际置信度（工具未提供就标未知），结合异常字符、孤立符号/破碎行等质量特征。低质量页做有界重识别或保留异常标记，严重异常阻止自动入库；不默默丢整页，不把可疑ASCII乱码当作干净中文正文。
- 保存原始提取、规范Markdown、逐页来源、规则版本和变更摘要；在现有异常详情/资料详情提供检查入口，不恢复日常“清洗/批准”按钮。
- 新规则应用于新导入和明确重新解析的候选；不自动批量覆盖旧资料或人工修订。原件和旧活动版保留，失败可重试，人工编辑冲突必须拒绝。

## 3. 网页名称与操作一致性

- Web产品标题、品牌和页面标题使用“本地知识库”；Shiping桌面名称不改。内置知识库UI显示为“默认知识库”，内部shiping标识及桌面连接保持兼容；不擅自改名用户创建的库。
- 批量导出Markdown、下载MD、下载原件仍使用可下载链接语义，但样式、尺寸、焦点和禁用状态与普通操作按钮一致。窄屏操作区可换行，失败显示中文原因。
- 保留四个主要区域：资料库、知识库问答、任务与索引、设置与维护。资料编辑/导出、回收站、两种索引和备份能力保持。

## 4. 聊天式知识库问答

- 当前知识库下展示会话列表、用户/助手消息、底部输入框；Enter发送、Shift+Enter换行；流式输出、停止、重试、新会话、切换会话。生成中避免重复提交。
- 每次回答先检索当前有效资料，回答附可核对的来源编号与片段；“检索依据”和“诊断”折叠展示。保留仅检索模式，不强制每次问题都调用云端回答。
- 问答消息和引用快照持久化SQLite，按知识库隔离。项目移入回收站后不能继续发问，恢复后保留会话；永久清理预览包含聊天数据。消息历史是当时依据的审计快照，不能作为新问题的当前有效知识库证据。
- 生成前/完成时检查来源和项目是否仍有效；冲突、停止和断网以中止/失败状态结束，不保存为“完整成功”。来源不足时明确说明，模型返回的来源编号须对应本轮实际证据。
- 模型配置由本地后台持有，文件权限600，不回传浏览器密钥、不写日志/Git。通过现有进程认证RPC复用桌面已配置的DeepSeek对话模型；同步后后台可独立运行，不重新依赖桌面常开。网页可查看配置状态并显式更改，不自动覆盖用户之后在网页选定的配置。
- 聊天使用独立的知识库问答指令，不沿用桌面的面试人设。Markdown安全渲染，原文和模型输出均不能执行HTML/脚本或后台指令。

## 5. 召回主链及可选reranker

问题处理 → 向量40 + BM25 40 → RRF融合20 → 可选本地reranker → 去重/补充相邻片段 → 最多8片/6000字符 → 回答。

- 取消独立实体召回及第三路加票。人名、URL和编号仍保留在原问题与BM25词项中；实体保留校验不等于额外实体召回。
- 修复已复现的RRF同分问题：融合分相同采用明确稳定的次序（优先BM25排名，再向量排名，再稳定ID），诊断保留两路排名。只在同分时处理，不根据题号硬编码，也不先任意调全局权重。
- 本轮下载并独立部署BAAI/bge-reranker-v2-m3，仅重排有限候选。通过固定语料对照和本机耗时/内存验证后默认启用；保留关闭开关。重排响应需校验索引/ID、数量、有限分数和当前修订；超时、不可用或无效响应回退原RRF，并显示降级原因。未配置不得标“精排已启用”。
- 最终继续做正文/重叠去重与完整单元预算。问题改写与重排不改变向量指纹，不要求全库重建。

## 6. 口语问题规范化、改写与扩展

- 先用规则去除独立语气词、重复空白及明确的提示包装；原始问题始终保留。独立问题不拼入无关旧话题，只有指代/省略时补近期必要上下文。
- DeepSeek按需改写：长口语/噪声问题或追问才调用，简单明确问题跳过；用户可关闭。返回一个独立检索问题和少量候选表达，限制长度/数量、超时与输出格式。
- 同时保留原问题召回，改写仅作为补充；两次向量结果先在同一路内合并，再与BM25融合，避免改写数量变成额外投票。稀疏词项也保留原词，扩展词不覆盖原始精确标识。
- 不允许改写凭空增加人名、URL、编号等事实；违反校验、格式错误、超时/服务失败时直接使用原问题，不阻断本地检索。诊断展示原问、规范问题、补充表达、调用原因与回退原因，模型分数不解释为正确率。

## 数据、迁移与安全约束

- SQLite使用加法迁移扩展会话/消息记录；拒绝未知更高版本，不回写旧JSON。上线前退出写入者并完整备份/验证恢复；保留旧库、旧应用和旧集合。
- 下载和二进制上传沿用回环Host/Origin/本机会话/CSRF；桌面同步仅用私有进程认证。外部网页不能配置模型、发起问答或读取资料。
- 原文件只读保留，本轮不永久清理真实用户数据。API Key、原件、向量、会话和模型配置不进入源码副本/GitHub。pcworkspace只同步源码且先比对用户修改。

## 验收与回退

1. 实际5.5MB/79页文件通过上传校验进入任务；大文件、非法base64、部分中断、取消/重试、同批失败继续、重复导入都有回归。
2. 合成噪声/中文OCR、代码、金额、URL、公式和表格对照，验证规则不会误删关键内容；难页显示异常和来源，不伪造修复。
3. Web名称/下载按钮一致，聊天输入、流式/停止/会话切换、来源与折叠诊断通过实际UI检查。
4. 历史20题使用固定7份活动语料离线/隔离评测（用户新上传资料不混入）；另加保留题和无答案/多轮/口语题。对比原RRF、同分修复、改写与可选重排；不把17/20离线回放或关键词匹配当作答案准确率。
5. 本地单测、网页API/CSRF/认证、类型检查、构建及打包运行时通过。DeepSeek先用本机假服务做协议/失败测试，再用合成资料做最少量已授权真实调用。
6. 新增模型/清洗/查询调用和耗时可见。保存完整回退点，更新操作台账与本机副本，GitHub保持不写入。

## 设计检查后补充（开发者裁定，无新增产品选择）

- 二进制上传在任何readJSON之前分流；在限额、类型、完整性验证后持久入队。提交标识用于已接收但响应丢失的幂等恢复，取消明确区分接收中与已排队任务。
- 解析进度使用独立、白名单化的结构通道，stdout仍保持单个最终结果；不混入原文或密码。区分取消、无进展超时和总时限，进度带页码/总页数及阶段；重启按租约恢复，不能假称继续未保存的OCR中间结果。
- OCR返回真正原始文字与行块位置/置信度；清洗仅改派生正文，来源映射以派生位置重新计算。旋转后无法可靠反投影的坐标标未知，不假称精确定位。置信度不等同正确率。
- 统一生成最终evidence[]：编号、文档/修订、片段、来源位置和正文，与实际6000字符预算中的上下文一一对应，包含最终选中的邻片。模型、引用快照、UI都使用这一份；不会把粗排20条全当作已引用。
- 每会话只允许一项活动生成，以请求ID保证幂等；仅最近有限条成功消息进入历史。停止和断连同时中止改写/检索/生成，保留失败/中断状态；启动时将此前未完成生成收敛为已中断，不能把部分回答当可靠历史。
- 桌面在配置就绪后推送当前DeepSeek对话profile及配置版本，后台未被网页显式覆盖时才接收。保留必要的自定义请求头和可支持的代理设置，传输不支持时明确报错，不悄悄改用其他平台；设置调用/输出上限。网页状态不显示密钥。
- 向量路内重复输入先合并（同ID取最高相似度），再按相似度/稳定ID排序；BM25按分数/稳定ID排序；融合同分按BM25排名、向量排名和稳定ID。保留原问题，改写只作补充，不以改写条数增加RRF权重。
- 基础Library和Catalog共同支持新schema，统一幂等加法迁移，禁止Catalog将版本写回5。网页资料备份明确不含完整聊天历史；聊天历史另随完整SQLite备份保留。永久清理预览包含会话/消息/引用快照数量，只清理该项目记录。
- 回退使用升级前同一时点完整快照与匹配旧应用，保留升级后库/原件与新会话用于合并。当前已达9份有效资料，任何固定7份课程评测都使用隔离快照，不回写生产语料。

用户最新确认：安装本地reranker并继续其余全部计划。本机M5/16GB，使用独立Python环境和本地模型目录，优先验证MPS，回退CPU需明确记录。模型及依赖使用官方仓库/包源，固定revision/已安装版本并记录哈希；不混入Chroma环境。

## 实机联调补充：代理兼容

部署时检测到桌面实际路线为本机 HTTP 代理。为完成已授权的 DeepSeek 复用，后台增加同路线 HTTP(S) 传输，系统代理先解析为固定首条路线，不自动回退直连；证书校验保留，模型接口重定向不跟随。网页独立配置优先，密钥仍只在私有配置保存。原先“只支持直连并明确提示”的实施取舍已被此兼容实现替代，不改变资料本地处理或模型发送范围。
