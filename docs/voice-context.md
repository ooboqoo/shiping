# 对话模式：摘要上下文与双路语音

这一改动让追问可以结合最近几轮的问题、AI 建议和自己的实际发言，同时让本轮问题尽快进入回答模型。默认开启最近 3 轮摘要上下文、约 1000 个估算 token 的历史预算，以及电脑声音和麦克风双路录入。

## 使用方式

- 「设置 → 对话模式」可以开关摘要上下文，设置最近轮数（界面 1–20 轮）和历史预算（100–4000 个估算 token）；底部状态栏也提供上下文开关。
- 音频来源可选「电脑声音 + 麦克风」「仅电脑声音」「仅麦克风」。需要配置百炼 ASR Key，并允许系统音频和麦克风权限。
- 电脑声音按原有自动／手动提示规则触发回答；麦克风发言只作为实际发言背景，不单独触发或取消提示。因此「仅麦克风」适合记录自己的发言，不能单靠麦克风生成面试官问题的提示。
- 左侧转录和自动保存的 Markdown 记录区分「面试官·电脑声音」和「我·麦克风」。这些标签来自采集通道，不是声纹识别；电脑的其他播放声音也可能进入电脑声音通道。
- 提示卡显示回答首字的接收／界面显示耗时及历史摘要用量。该计时从提交提示或收到 ASR 句子结束事件附近开始，不包含声学上的停顿检测和 ASR 传输全程。

## 上下文如何构建

`src/shared/conversation-context.ts` 负责纯本地选择和预算。只在最近 N 个已完成问答中选已有摘要；没有准备好的摘要就跳过，不把更旧轮次补进来，也不回退到旧 AI 全文。预算优先分配给较新轮次，再按时间先后展示。当前问题保持完整，不受历史预算截断。

历史摘要、自己的实际发言、重写时的上一版提示共用同一个历史预算。约 1000 token 是所有这些历史背景的总预算，不是每轮各 1000，也不是机械截取聊天末尾的 1000 个原始 token。预算沿用项目的本地 `estimateTokens()`，不是供应商精确 tokenizer；本轮问题、系统提示、资料库和已启用的外部检索材料不属于这个历史预算。

摘要明确区分面试官问题、自己的实际发言和 AI 建议，不能把 AI 建议当作自己已经说过的话。缓存仅存在于当前进程的会话内，最多保留 20 份；完整转录仍由原有会话记录功能保存。关闭上下文时不附带这些历史背景，也暂停后台摘要。

## 后台摘要与首字路径

`src/main/conversation-summaries.ts` 在空闲 1500ms 后，以最新完成轮次优先、一次一个请求的方式生成摘要。每次摘要最多请求 400 个输出 token，提示词要求约 250 个中文字以内，超时 8 秒，不自动重试。摘要使用对话模式的模型和代理配置，但独立使用短提示词、请求关闭思考，不携带资料库或调用外部检索；这会产生额外模型请求和费用。

对方开始说话或前台请求启动时，暂停队列并中止正在进行的摘要。前台同步读取已有缓存，不等待摘要完成。失败、超时或未完成时直接省略该轮；清空和重写会使旧结果失效，过期异步结果不能写回。

`src/renderer/src/conversation/index.tsx` 将第一个回答文本片段立即写入 store，后续片段再按动画帧合并。计时区分 reasoning、空白和有效回答文本；界面显示耗时通过提交后的渲染机会回报，不再人为多等一帧。

回答请求保留上游 `apiFetch`、关闭思考／思考强度设置和外部知识库能力。若启用了外部知识库，仍按上游设计等待检索返回，这段时间可能增加首字延迟。短追问的检索 query 只从电脑声音通道补充前一句，避免把自己的麦克风发言误当作对方问题。

摘要请求单独兼容新 GPT/o 系列所需的 `max_completion_tokens`；普通回答请求保持上游行为。

## 双路采集与生命周期

`audio-capture.ts` 为电脑声音、麦克风分别创建采集和处理链，输出带来源标记的 16kHz PCM；监听增益保持为 0，避免把麦克风直接回放到扬声器。它不消除外部通话、扬声器串音或回声，实际通话建议使用耳机并检查两路转录。

`transcription.ts` 为两路各维护一个 DashScope WebSocket 会话，按来源路由 PCM、识别修订和最终句子；这会占用两路 ASR 会话及相应费用。双路中任一路启动失败会清理已启动资源并报告错误，不显示为双路正常运行。

开始／停止使用代次标识和串行生命周期，取消旧启动不能终止新的启动。取消尚在握手的 WebSocket 时保留关闭阶段的错误处理，避免未处理异常；真实 WebSocket 的本地回归覆盖这个场景。停止识别会等待末尾识别结果，最多排空 700ms；页面切换和快速重启也经过这条生命周期。

## 验证和性能边界

适配上游 3.6.0 主分支后，验证命令为 `npm test`、`npm run lint`、`npm run build` 和 `npm run test:proxy`。测试覆盖历史预算、开关持久化、未就绪摘要跳过、后台抢占与过期结果、完整当前问题、双路 PCM 和 WebSocket 路由、启动取消、停止排空、首片段立即更新，以及原有代理／外部知识库／思考设置。

此前在基于 3.4.0 的本地实现中，用 4 条合成的 ASR 最终句子驱动真实模型及构建后的界面，观察到首字显示约 3.54 / 2.01 / 2.01 / 1.01 秒；它们不包含实际声学停顿和 ASR 传输，也不是此 3.6.0 分支的端到端测速。此前 Windows 上曾验证实际电脑声音和默认麦克风都能输出 PCM 并连接各自 ASR 会话；这不代表真实会议的转录准确率、回声表现或 macOS 已验证。

3–5 秒是优化目标，不是保证。供应商负载、网络、模型思考和可选外部检索都可能影响首字；摘要也可能丢失细节。当前优先保证新问题不等待摘要，真实通话和 macOS 双路权限仍需进一步验证。
